### 3. Resumen

Este proyecto aborda la desconexión digital en instituciones escolares mediante el desarrollo de una aplicación web de trivia interactiva con arquitectura *offline-first*. Ante la problemática frecuente de la intermitencia de red, se diseñó un software dinámico en HTML, CSS y JavaScript capaz de retener de forma segura los puntajes de los participantes en la memoria local (`localStorage`), implementando un escuchador automático en segundo plano que migra los datos hacia una base de datos en la nube (Supabase) de forma masiva en el instante preciso en que se recupera la conectividad.

### 4. Introducción

En entornos pedagógicos ideales, las aplicaciones educativas dependen de internet constante. Sin embargo, en la práctica cotidiana escolar, los servidores y las señales de Wi-Fi sufren caídas frecuentes. Cuando un software educativo común pierde conectividad a mitad de una actividad, los datos del progreso del alumno se destruyen, generando frustración. Este proyecto expone cómo las metodologías de desarrollo de software modernas pueden mitigar las deficiencias de infraestructura física mediante código inteligente.

### 5. Hipótesis

*"Es posible garantizar la continuidad pedagógica y el registro íntegro de calificaciones en una aplicación digital escolar ante cortes imprevistos de internet mediante una arquitectura de sincronización diferida controlada por hardware de red."*

### 6. Objetivos

* **Objetivo General:** Desarrollar una aplicación de trivia educativa híbrida tolerante a fallos de red.
* **Objetivos Específicos:**
1. Estructurar una interfaz semántica en HTML y CSS que proporcione feedback visual pedagógico a los alumnos.
2. Implementar persistencia local temporal para almacenar participantes sin sobrescribir registros previos.
3. Programar un módulo de sincronización asíncrona automática (`Bulk Insert`) conectado a la API de Supabase.



### 7. Metodología

Se utilizó un diseño metodológico experimental basado en desarrollo ágil.

1. **Fase de maquetación:** Creación de pantallas SPA (*Single Page Application*) controladas mediante clases CSS de visibilidad (`.oculto`).
2. **Fase lógica local:** Programación en JavaScript de estructuras de objetos mutables para retener los estados de juego de cada alumno.
3. **Fase de resiliencia:** Diseño del "guardián de red" mediante el evento global `window.addEventListener('online')` para automatizar la migración diferida de arrays de objetos JSON almacenados localmente.

### 8. Resultados

El software fue sometido a pruebas de estrés simulando la desconexión de red. Al apagar el adaptador de Wi-Fi, la aplicación continuó operativa: los alumnos jugaron, recibieron su desglose de respuestas correctas/incorrectas y el sistema almacenó con éxito las puntuaciones en el búfer local. Al restablecer la red, el navegador disparó el evento en un segundo plano, inyectando de forma limpia las filas pendientes en la base de datos centralizada de Supabase sin duplicaciones y liberando la memoria del dispositivo.

### 9. Conclusiones

Se validó la hipótesis inicial de forma concluyente. La práctica tecnológica en las escuelas no tiene por qué verse limitada por las carencias de su conectividad. Aplicar un enfoque arquitectónico centrado en la tolerancia a fallos permite que el software absorba el problema físico de la red, demostrando que un diseño de código robusto es la solución más eficiente para cerrar la brecha entre el aula teórica y la realidad del aula práctica.
